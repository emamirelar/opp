Implementation Notes:

  • Component: <app-approve-opportunity-dialog> in features/partnerships/opportunities/components/opportunity/approve-opportunity-dialog/
  • Triggered by: customStageChangeHandler input on <app-stage-workflow> component
  • Flow: User clicks Approve → customStageChangeHandler('GO', 'Approve') → Show this dialog → Return CustomStageChangeResult { proceed: true, comment: rationale }
  • API: Enhanced POST /api/workflow/approve with ApproveWorkflowRequest body (entityName, entityId, rationale, confirmationAcknowledged, executiveId)
  • Executive Lookup: GET /api/opportunity/{opportunityId}/executives returns Director/Deputy Director options from EntityUserRole table
  • Executive Assignment: Mandatory field - OrgUnit Director pre-selected (marked as "Suggested"), stored on Opportunity.ExecutiveId
  • Validation: Submit disabled until checkbox checked AND rationale provided AND Executive selected

Implementation Notes:

  • Workflow Panel: EXISTING <app-stage-workflow> - no action buttons because record is in terminal stage (GO)
  • Stage Change History: EXISTING tab shows decision details (decision maker, date, rationale) from WorkflowLog
  • Submit action: Requests transition IDENTIFY & PROFILE → GO (initiates approval workflow)
  • Approve action: Confirms transition IDENTIFY & PROFILE → GO (completes the workflow)
  • Data immutability: Backend throws BusinessException (400 Bad Request) for any edit attempts on GO/NO GO/CANCELLED stages. Permission endpoint returns canUpdate: false and isImmutable: true
  • Permanent vs Temporary: GO stage is permanent (no reopen). NO GO and CANCELLED can be reopened by OM, which lifts immutability
  • Statement: Locked, cannot regenerate AI content
